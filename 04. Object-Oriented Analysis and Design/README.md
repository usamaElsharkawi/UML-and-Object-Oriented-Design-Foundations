# 04. Object-Oriented Analysis and Design

This section bridges the gap between business requirements and technical
design — the core of the OOAD process.

## Lectures

1. **Fundamental Object-Oriented Analysis and Design Concepts** — The ideas
   that underpin the analysis and design workflow.
2. **Collecting Requirements** — How to gather and document what a system must
   do (includes a `requirements.pdf` example).
3. **Mapping Requirements to Technical Descriptions** — Turning business
   requirements into a form engineers can work with.
4. **Why Do We Need a Common Descriptive Language** — The motivation for a
   shared modelling language (UML).

## Key Takeaways

- The difference between analysis (the "what") and design (the "how").
- How to collect and structure requirements.
- Why a common descriptive language is essential for communication across
  teams.
